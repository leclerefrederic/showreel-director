# Engine and scripts (style-neutral plumbing)

The `engine/` and `scripts/` folders hold plumbing only: time, beats, audio clock, controls, build, tests. They have no palette, font, shape, effect or script of their own, so they cannot bias the look. The creative code (`main.js`: scenes, layouts, effects, text, props) is always written from the brief and storyboard. Reuse the plumbing so the effort goes to the design and the known timing, audio and controls bugs do not come back.

## Project layout
The full folder layout is in SKILL.md (Project layout). Per version: `project.json` (copy `engine/project.template.json`), `main.js` (start from `engine/main.template.js`), `dist/` (built output and exports).
Paths in `project.json` are relative to the `vN/` folder (`../assets/prepared/audio-01-<slug>.mp3`, `../analysis`). A new version is a copy of the previous `vN/` folder.

## Commands (run from the skill folder; `<vN>` is the version folder)
- Effects lab (opens on the six moods, then only the effects of the chosen ones; `--full` opens on every effect; `--mood "Kinetic punch"` opens on the moods already chosen on the look board (names of the Packs table); `--ui` also takes g_title, g_hint, g_show, g_all, g_change, g_packs, g_back): `python3 scripts/build_effects_lab.py --out <project>/qa/lab-effects.html --bg #... --fg #... --accent #... --accent2 #... --font <font file> --family "<name>"` writes a page animating the effects of the catalogue in the user's palette and font, with a sample-text field, category filter, hearts and a copy-my-picks button. Present it in round 3.
- Shared helpers (not run directly): `scripts/_common.py` (brand arguments, colour validation, font embedding, page templating for the Python builders) and `scripts/_reel.js` (reel loading, canvas stub and font registration for `scripts/harness.js` and `scripts/export_mp4.js`).
- Backgrounds: `engine/backgrounds.js` (`window.SRB`, 23 procedural backgrounds in five families: Solid, Gradient, Pattern, Texture, Animated) draws any of them from the palette: `SRB.draw(id, g, W, H, t, pal, {reduced})` with `pal = {bg, fg, accent, accent2}`; animated ones freeze when `reduced` is true and nothing flashes; `SRB.list` gives `{id, family, name, desc, animated}`. `build.py` inlines the file only when `main.js` mentions `SRB`. **Music reaction (guard rail, not a rule):** `ctx.music` is true only while a track is audible (a track exists, the viewer chose sound, not muted; the harness and the MP4 export set it from the embedded track, `--silent` / `--no-audio` turn it off on the harness and the MP4 export; the exported file is then named `..._muted.mp4`, because an MP4 bakes the beat reaction into the pixels: make a muted version for feeds that play without sound); `SR.signals(ctx)` returns `{pulse, hat, energy, beat}` or `null` when there is no music, it is muted or reduced motion is on. Pass `{sig: SR.signals(ctx), mood: SRB.moodFor(<effects pack>), reduced: ctx.reduced}` to `SRB.draw` and the animated backgrounds (particles bounce, stars twinkle harder, aurora swells, spotlight and scanlines pulse, waves rise, drift sways) follow the track, scaled by the mood (punch 1, tech .8, playful .7, clean .4, cinematic .35, deadpan .15); reactions move size and position, never brightness flashes, and stay pure functions of time. `SRB.sequence(g, W, H, t, pal, o, [{id, from}], fade)` keeps one background running across scenes with crossfades (call it with the reel time, not the scene time); `SRB.blend` crossfades two backgrounds. Silent reels and muted playback stay calm by construction. Background picker: `python3 scripts/build_background_picker.py --out <project>/qa/backgrounds.html [--message "..."] [--bg --fg --accent --accent2 --font --family] [--ui ui.json --lang fr]` draws every background live in the user's palette with the reel's message over it; the user picks one for titles, one for content scenes and one for the closing ("Titles: aurora | Content: grid | Closing: solid"). Add a background with `add(id, family, name, desc, animated, fn)` in `backgrounds.js`; the look board and the picker read the list from that file.
- Look board (previews show titles at regular weight; the bundled fonts are static Latin files): `python3 scripts/build_look_board.py SPEC.json --out <project>/qa/look-board.html [--ui ui.json --lang fr]` builds a page with 2 to 4 design packages (palette, background, font pair, effects mood) drawn as real frames with the reel's message; the user picks one or mixes elements; the script refuses unknown fonts, unknown effects moods, bad colours and identical packages (spec format in the script header).
- Font picker (previews come from the Latin woff2 files bundled in `engine/fonts-preview/`, embedded in the page; a font without a bundled file loads online or falls back to a system font and its card says so; the bundle is made once by the maintainer with `python3 tools/fetch_font_previews.py`, on a machine with network): `python3 scripts/build_font_picker.py --out <project>/qa/fonts-picker.html [--bg --fg --accent --accent2] [--ui ui.json --lang fr]` builds a page over the curated free fonts in `engine/fonts-free.json` (open licence, embedding allowed; filter by mood and kind; one pick for titles, one for text; "Copy my picks"). `python3 scripts/fetch_font.py "<name>" [--dest DIR] [--weights 400,700] [--dry-run]` downloads the chosen font and its licence from the Google Fonts repository (needs network; otherwise it prints the specimen page for a manual download); give the folder to `organize_assets.py --from`. Add a font by editing `engine/fonts-free.json` (name, repository folder, kind, moods, note; open licences only).
- Film layer (optional mode, experimental: one `main.js` with one `render()` stays the default and is what the steps describe): `engine/film.js` (`window.SRF`) assembles one render module per scene, `{name, t|bar|k, render(g, lt, ctx), transition: {type, duration, params}}`, into a reel: `window.SHOWREEL.render = SRF.film({scenes, palette, background, overlay}).render`. A scene module draws with its own local time `lt`; what crosses scenes (a background sequence, music reaction, a persistent element) is a function of the film time in `background(g, t, c)` and `overlay(g, t, c)`. A transition is a relation between two consecutive scenes, stored on the outgoing one (`type` `'cut'` or a name of `SRT.list`, `duration` in seconds, `params`): it overlaps the end of the outgoing scene and the start of the incoming one, centred on the cut (from T - d/2 to T + d/2, `d` capped at the shorter scene), so scene starts and the film's length do not change; the outgoing module keeps drawing past its end (`lt` beyond its duration, `u` 1), the incoming one draws from `lt` 0 (`ctx.pre` is true before its start). During a transition both scenes are drawn into off-screen canvases and mixed by the transition of the catalogue; outside one, each scene is drawn straight onto the stage, so the harness checks see it as usual. **Film format with the montage in `film.json`** (what the desktop app's Build asks for; a chat session may use it too): the version folder holds `film.json`, `{schema, scenes: [{name, t, duration, transition?: {type, duration, params?, instruction?}}]}` (scene names are the storyboard IDs, `t` and `duration` in seconds, the transition leads to the next scene, no transition means a cut on the beat); `build.py` inlines it as `SR.data.film`, and `main.js` (start from `engine/main.film.template.js`) is one module per scene in an object keyed by those names plus ONE call `SRF.fromData(MODULES, {palette, background, overlay})`, which reads starts, durations and transitions from the data and throws when a scene has no module: never copy the montage into `main.js`, and never edit `film.json` (it is rewritten from the montage). A transition's `instruction` (for a match cut: which element becomes which) is for the two neighbouring modules. Transitions marked as previews in `engine/transitions-preview-only.json` (Morph, Match cut, Ink/paper inversion, Curtain, Mirror split, Star reveal: the lab draws them for its stand-in scenes only) must not be used in a film; `tools/check.py` keeps that list equal to what the probe finds. `node scripts/harness.js <page> --scene S02` limits the logic test to one scene's frames (the report already names the scene of each issue).

`engine/transitions.js` (`window.SRT`) is GENERATED by `python3 scripts/export_transitions.py` from the effects lab (`14-transitions.js`, `22-transitions-more.js` and the lab's helper block, unchanged except that the lab's stand-in scenes become the real ones): do not edit it, `tools/check.py` fails when it is out of date. `build.py` inlines `film.js` and `transitions.js` only when `main.js` mentions `SRF`; the harness, the player test, the contact sheets and the MP4 export need nothing else (hosts without a DOM provide `SR_CANVAS_FACTORY(w, h)`; `harness.js` and `export_mp4.js` do). Limits today: the catalogue's transitions run in a 640x360 space scaled to the stage (an iris is an ellipse in 9:16, effects that use their own off-screen layers are softer than the scenes); 36 of the 42 transitions run between two real scenes and 19 show both scenes together at some point, the others are demonstrations that draw their own shapes (Morph, Match cut), leave the incoming scene inverted (Ink/paper inversion), or are drawn for the lab's stand-ins (Curtain, Mirror split, Star reveal): `node scripts/test_film.js <built page> --all` prints the state of each. `node scripts/test_film.js <built page>` checks on a built film that a frame in the middle of each transition holds pixels of both scenes and that the same frame is byte-identical when drawn twice (needs `@napi-rs/canvas`); `evals/film-spike/` is a three-scene test film (a push and an iris) used by `tools/check.py`.
- Feasibility: `python3 scripts/feasibility.py --duration S [--scenes N] [--words N | --words-per-lang en=30,fr=33] [--langs N] [--portrait] ...` checks duration, scene count, text amount, languages and formats against the standards in `references/feasibility.md` and prints OK / TIGHT / NOT FEASIBLE per check (`--help` lists every option).
- Environment check: `python3 scripts/check_env.py [--json] [--node-path DIR]` (`--node-path` accepts several folders separated by a colon; save `--json` to `<project>/qa/check-env.json`; `analysis/env.json` is the audio envelope, not this) lists required and optional tools (numpy, ffmpeg, Node, fontTools, brotli, jsdom, @napi-rs/canvas, headless browser), what degrades without each, and the install hint. It never installs anything.
- Audio analysis: `python3 scripts/analyze_audio.py <project>/assets/prepared/audio-01-<slug>.mp3 --out <project>/analysis [--bpm N] [--first-beat S]` prints other plausible tempi and, if the confirmed tempo or first beat is wrong, can be rerun with `--bpm` and `--first-beat`; it prints tempo, bar start times, probable drops, and **breakdowns** (bass out for 4+ beats) with the **return** (bass back) and the bar to hit on, then writes `beats.json` (with `breakdowns` and `returns`) and `env.json`. On tracks with no loud/quiet jump the drop test finds nothing; use the returns instead, or choose emphasis moments from the bar energy table and by ear. It assumes a steady tempo: verify the bar table by ear and fix tempo changes or a late first beat by hand.
- Licence of a supplied file: `python3 scripts/organize_assets.py <project> --licence 'font-01=web and app embedding included (invoice 123)'` records what the user states; a font held because its note or its own embedding flag (fsType) forbids embedding, or because the note and the font's metadata disagree, can only be approved after this step (or excluded, or replaced by a free font; with a desktop-only licence deliver the MP4 only).
- Organiser: `python3 scripts/organize_assets.py <project> [--from DIR] [--apply | --set id=status | --redacted id=PATH | --register | --md | --check]` puts files in `assets/source` (originals), `assets/prepared` (typed names) and `assets/generated`, keeps `assets/MANIFEST.csv`, holds sensitive or unlicensed files until decided, and checks names, manifest, stray files and version paths. See `references/assets.md`.
- Asset audit: `python3 scripts/audit_assets.py <folder with the supplied files>` (before the organiser has run) or `<project>/assets/source` (after) flags weight, resolution, personal-data keywords (licence and consent notes are matched in English: read notes written in another language yourself), missing licences, fonts that forbid embedding, rights not confirmed.
- Build: `python3 scripts/build.py <vN>` writes one self-contained HTML and a weight report; fails over the budget. Fonts embed as woff2 when the `brotli` package is installed (`pip install brotli --break-system-packages`), otherwise as woff.
- Contact sheet (embedded images and fonts are awaited before drawing): `python3 scripts/build.py <vN> --qa-step 4` (or `--qa 0,17.4,40.6`, with `--qa-langs fr,en --qa-modes d,m --qa-tile 420`) writes `<project>/qa/contact-<vN>[-<cut>].html`, a page tiling frames per language and format. View it with a screenshot tool, or give it to the user.
- Logic test (with `@napi-rs/canvas` on NODE_PATH the embedded fonts are registered and text is measured for real, so wrapping and collisions run on the layout that ships; without it widths are estimated, and the run says which): `node scripts/harness.js <vN>/dist/index.html --step 0.25` renders every frame in each language and format with a canvas stub. Reports exceptions, non-finite values, text collisions (two different texts overlapping for 3 or more consecutive samples), text drawn outside the stage and the strings drawn per scene. Exit code 1 if there are issues. With real fonts measured, aim for 0 issues; when widths are only estimated (no canvas package), an issue on a wide line may be a false alarm: check it on stills and record the decision. `--silent` renders as if the music were off (no reactive visuals).
- Decision sheet: `python3 scripts/build_decision_sheet.py spec.json --out <project>/qa/decision-<name>.html [--bg --fg --accent --accent2 --font --family]` builds a one-file page where the user picks an option per item (swatches, type specimen, required notes, copy decisions). Spec and guardrails in `references/review-tools.md`.
- Scene cards: `python3 scripts/build_scene_cards.py storyboard.md --out <project>/qa/cards-scenes.html --title "..." [--bg --fg --accent --accent2 --font --family]` writes the visual sheet used before the scene-by-scene review.
- Stills: `NODE_PATH=... node scripts/export_mp4.js <vN>/dist/index.html --stills 4,12,21 [--mode m] [--cols 3 --tile 480] [--stills-report] --out <project>/qa/stills.png` (`--stills-report` also prints, per frame, how much of it is covered, the content box, empty frames and content touching the edge: an objective check when you cannot look at the PNG) renders frames at those times into one PNG (no browser, no ffmpeg) so you can look at the result yourself.
- MP4 export: `NODE_PATH=<dir with node_modules/@napi-rs/canvas> node scripts/export_mp4.js <vN>/dist/index.html --out <vN>/dist/<slug>_<vN>_<mode>_<lang>.mp4 [--mode m] [--start S --end S]` renders frames without a browser and muxes the track with ffmpeg (about 100 fps; default size is the stage size, 1600x900 or 900x1600: add `--scale 1.2` for 1920x1080 or 1080x1920). Install the canvas package in a scratch folder (`npm install @napi-rs/canvas`) after asking the user.
- Notes pad: `controls.notes: true` in `main.js` adds a Note button and the N key to the player (pause, timestamped note with scene ID, format and language, copy; the stamp follows seeks, and a note within 0.6 s of a cut is labelled with both scenes). Labels come from the `ui` block of `main.js`, looked up under `reviewLang` (a key of `ui`, for example `reviewLang: 'fr'`) when it is set, else under the reel language (keys note, noteAt, noteHint, noteAdd, noteCopy, noteCopied, noteClose, noteHeader, noScene, cutIn). The same `ui` block holds the player's own labels (play, pause, muted, sound, rp, lp, fm, lg, startSound, startSilent, reduced, reducedOn): translate every key for each reel language. Review builds only.
- Player test: `NODE_PATH=<dir containing node_modules/jsdom> node scripts/smoke_player.js <vN>/dist/index.html` checks overlay, start, pause, seek (to half of the reel's duration), switches, that sound controls are hidden without a track, and the notes pad when present (replay is not tested); add `--release` to fail if the notes pad is in the build (install jsdom in a scratch folder with `npm install jsdom`).

## project.json keys
`title`, `main`, `track` (path under `assets/prepared` or `assets/generated`), `analysis_dir`, `duration` (seconds: set it whenever the reel is shorter than the track; `build.py` warns if the track is much longer and trims the embedded audio to `duration` + 1 s with ffmpeg; without it the reel lasts as long as the track), `fonts` (family, weight, path), `images` (`{"key": "../assets/prepared/shot-01-....png"}`: embedded as data URIs; draw with `const im = SR.img('key'); if (im) g.drawImage(im, ...)`, it returns null until the image is ready; a frame sequence is one key per frame), `tokens` (CSS variables), `track_start_bar` (top level: the track's bar that plays at 0 s; use it to land the drop on a scene; the beat map, envelope and trimmed audio shift with it; a cut may override it), `cuts` (`{"short": {"duration": 15, "track_start_bar": 9}}`: build one with `build.py <vN> --cut short`; `SR.data.cut` tells `main.js` which schedule to use), `weight_budget_mb`. In `main.js`, `slug` (short ascii name) is used for export file names. Every path is checked against the manifest by `build.py`.

## What the engine provides
`window.SR`: `clamp`, `lerp`, basic `ease`, `K_(beat)`, `barT(bar)`, `beatInfo(t)`, `envAt(t)` (kick/hat/energy), `setScenes([...])` and `sceneAt(t)`, `stage()` letterbox, `drawFrame()` (pure function of time, language and format). The player supplies the start overlay (language, format, reduced motion, with or without sound), the controls declared by the brief, audio as master clock with latency compensation, a 0.6 s fade-out, a silent fallback, replay or loop, and keyboard shortcuts. `ctx.reduced` comes from `prefers-reduced-motion` or the player's toggle. Controls the brief did not ask for are hidden.

`window.SRK` (`engine/kit.js`, inlined with core.js): style-neutral drawing helpers so each project does not rewrite them: text with scale/alpha/rotation, fit-to-width, per-letter control, slam-in, rings, rects, progressive check mark, screen shake and flash lists, scramble, and a confetti cannon (one celebration per film). Colours, fonts and wording are always passed in by the project (`SRK.init({title, mono})` sets the two font families). Read the header of `kit.js` for the signatures. Use what the brief needs; the kit adds no look of its own.

## What it deliberately does not provide
Effect choices, palettes, fonts, scene layouts, wording, translations, portrait remapping (the kit only provides the low-level helpers named above). Build those from `effects-catalogue.md` and the storyboard. If you copy a pattern you saw in an earlier project, check that the brief actually asks for it.

## Known limits
The harness cannot see text that overflows a card or panel inside the stage, nor clip regions: look at stills (`export_mp4.js --stills 4,12,21 --out qa/stills.png`, then open the PNG) around every text-heavy scene in each format. No browser is guaranteed in the session: contact sheets may need the user's eyes or a screenshot tool. The harness measures text with an approximate width, so treat its overflow and collision warnings as leads and confirm visually. Slam-in frames (text scaled up for a few frames) can show up as "outside the stage" on purpose. The audio analysis handles constant tempo only.
