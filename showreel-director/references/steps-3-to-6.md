# Steps 3 to 6 detail: build, formats, verify, iterate

Craft detail is in `build-guide.md`; plumbing and commands in `engine.md`.

## Step 3 — Build

Starts only after the explicit go from Step 2b. Read `references/build-guide.md` first (architecture, text, readability, motion, music, accessibility). **Look test first** when the reel has more than 5 scenes (or the user asks): in a folder named `lt1/` (never counted as a version; `v1` is the first full build), build only the key-moment scene and one text scene, with the real palette, font, effects and music slice, open them in the player and validate the look on a decision sheet before building the rest (details in the build guide); if the session cannot run or show a build, say so and ask for the first full build to be judged as the look test. Rules that never bend:

- Research first, then write the animation. Build only from `assets/MANIFEST.csv`: embed approved files from `prepared/` or `generated/`, draw the rest procedurally, never pull in an unlisted image, font or sound; flag a placeholder instead of improvising. Anything you create yourself (a rendered image, a frame sequence, an icon, a voice) is saved in `assets/generated/` with a conventional name and registered with `organize_assets.py --register`.
- Start from the style-neutral plumbing in `engine/` and `scripts/` (`references/engine.md`). `main.js` is written fresh from the brief; `render(g, t, ctx)` is a pure function of timeline time, language and format. Each version is a new `vN/` folder copied from the last.
- Emotion drives the craft: pace, easing, holds, silence and reveals serve the intended feeling and tension shape from the brief, with one memorable moment.
- When there is a track, scene starts sit on real beats from the computed beat map (`scripts/analyze_audio.py`), never counted by hand (a silent film follows the reading budget); flashes stay under 3 per second.
- Implement the effects the user picked, by name; if one is missing, add it as a new style rather than substituting silently.
- Readability: each essential line is stable on screen for about 3 s or more, one idea per scene, no clipped or overlapping text.
- Backgrounds follow the style and the music without cutting against it: draw one continuous background with `SRB.sequence` (reel time, crossfades at scene changes) instead of resetting it per scene, and when there is a track pass `SR.signals(ctx)` and the mood of the chosen effects pack so animated backgrounds bounce or breathe with the beat (a slam or punch style bounces on the kick; a cinematic style breathes slowly). This is a guard rail, not a rule: it never applies without music (no track, sound off, muted, reduced motion) and the user can switch it off (`react: false`). Details in `references/engine.md`.
- Accessibility choices (muted viewing, contrast, flashing) are recorded in the brief, and every scene honours `ctx.reduced` (reduced motion: no shake, no flashes, softer scale-ins).

## Step 4 — Extra formats and languages

Details in `references/build-guide.md`. Portrait 9:16 needs a stated treatment per scene (dedicated composition or mapped layout). MP4: `scripts/export_mp4.js` renders the reel frame by frame without a browser and muxes the track with ffmpeg; promise it only if `check_env.py` shows node, ffmpeg and `@napi-rs/canvas` (ask before installing the canvas package), check one frame against the browser first, otherwise offer the HTML plus screen-capture instructions. Cut-downs are declared under `cuts` in `project.json` (`{"short": {"duration": 15, "track_start_bar": 9}}`) and built with `build.py <vN> --cut short`; `main.js` reads `SR.data.cut` to pick that cut's scene schedule, `track_start_bar` makes the cut start on that bar of the track (audio, beat map and bars are shifted: bar 1 of the cut is that bar), so check where the strongest moment falls in each cut; each cut is checked by the feasibility script and the harness like the full cut and delivered as its own file. Never translate literally: adapt idioms, keep a master-to-target dictionary, check font glyph coverage.

## Step 5 — Verify and publish

Details in `references/build-guide.md`. Before showing anything: run `scripts/harness.js` (exceptions, non-finite values, text outside the stage, text collisions, untranslated strings) and `scripts/smoke_player.js`, and look at contact sheets (`scripts/build.py <vN> --qa-step 4`). Re-read the **release gate** in `brief.md` before any publication or sharing: placeholders, unvalidated figures, pending authorisations or confidential data block it. Put the open points on a decision sheet (Resolve first / Waive and accept the risk, note required) and record every waiver in the decisions log. Placeholders and unvalidated figures can be waived by the user; personal data, confidential content and unlicensed assets are never published to a hosted public link (private local delivery is still possible, and you say why). Hand feedback over with a **review build** (notes pad on: `controls.notes: true`), and turn it off for the delivery build, checked with `smoke_player.js --release`. Report in plain terms what was and was not verified (audible sync, live playback, real phones, motion between still frames, anything from the storyboard not implemented). End with a delivery summary: files delivered, state of the release gate, how to share, what to re-validate, next version number.

## Step 6 — Iterate

Feedback arrives as notes from the pad, scene cards or a decision sheet; read them by scene ID and timecode. A note that changes a scene's timing or text is re-validated on the card sheet (Keep / Change) and needs a fresh go before the next delivery build; purely visual tweaks do not. Apply targeted tweaks one concern at a time. When feedback is ambiguous, restate your understanding in one line before changing it. Refer to scenes by their stable IDs (S01, S02…). Keep the decisions log (approved wording, rejected ideas, ditched scenes) in `brief.md` and don't reintroduce them. Re-run the harness and a contact sheet after each change touching timing or layout. Large storyboard rewrites: new version folder, text block swapped, layouts kept, then fix timing collisions the new wording creates.
