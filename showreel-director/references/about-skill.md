# Questions about the skill itself

Read when the user asks what the skill can do, how it works, how to work with it, or which effects it knows. Answer before any interview.

Triggers: "what can you do", "what are your skills / capabilities", "how do you work", "how do I work with you", "what effects do you know". Do not start the interview; answer, then offer to start. Answer in the conversation language, short and concrete.

**Capabilities / how it works / how to work with me.** Give three short parts:
1. *What I can do*: interview-led motion-design showreels and short animated videos (product teasers, brand or story pieces); self-contained HTML canvas by default, synced to a track when there is one; extra formats and languages; 248 previewable effects; audio analysis (tempo, beats, bars, drops); asset audit; feasibility checks against recognised standards (Netflix timed text, WCAG, EBU R128, Cinemetrics); iteration after delivery. State limits too: no style is assumed, MP4 export needs node, ffmpeg and a small canvas package (`scripts/export_mp4.js`), the visuals are procedural/vector unless assets are provided.
2. *How I work*: the steps in order (round 0 languages; working folder and environment check; interview on message, story, emotion, look and motion, sound and delivery, assets; feasibility gate; brief; style sheet and storyboard; scene-by-scene OK / MODIFY / DITCH review; look test; build; verify and release gate; iterate). Say that nothing is built before the brief, the style sheet and every scene are approved, and that every decision is a click or a choice (question rounds, decision sheets, scene cards, the effects lab, a notes pad in the review build) rather than a text block to approve.
3. *How to work with me*: bring any assets (logos, fonts, screenshots, music, scripts, brand guide) but none is required; answer the rounds in your own words or pick from options; say "express" for a shorter interview; use OK / MODIFY / DITCH on each scene; give feedback by scene number and timecode; heart your favourite effects in the lab and paste the picks back.
End by offering a quick way to see the range and ask which one: the **sample effects lab** (`engine/effects-lab-sample.html`) and, only if a file `demo/showreel-director-trailer.html` exists in the project's repository folder, one level above the skill folder (it is not part of the packaged skill: when the skill was installed from the `.skill` file it is usually absent, so expect to use the online link below), the **demo reel** (a ~90 s showreel made with this skill that explains it; present it with the file-presenting tool or give the path, tell the user to click "Start with sound", and mention that its music is Suno-generated and for non-commercial use only). If the demo file is absent, give the online demo link https://leclerefrederic.github.io/showreel-director/demo/showreel-director-trailer.html (opens in a browser, click "Start with sound"; the music is Suno-generated, non-commercial) and offer the lab. If the user accepts one, present it right away; afterwards offer to start their own interview. The demo is an example, not a template: do not reuse its look unless the user chooses it.

**"Which text effects do you know?" (or transitions, numbers, reveals, closings, camera, UI, graphic treatments).** Show, don't only tell: (a) present `engine/effects-lab-sample.html` (file-presenting tool, or give the path) so the user sees them animated, and tell them to type the category in its search box; (b) in the reply, list the requested categories from `references/effects-index.md`, grouped (Text in, Text out, Emphasis), each as name plus the one-line description, with a blank line between groups and no invented effects. For a long category, show the 12 most distinct ones and give the count and the way to see the rest. Never claim an effect that is not in the index.
