- 2026-11-10 (owner): Design System Manager, reusable packages. A package is a saved design system that pre-configures a new reel so that reels stay consistent (for example one package per brand): the look (palette, fonts, backgrounds, effects pack), the motion language (dynamics, pacing, transitions), the tone and form of the copy, format and duration defaults, and its resources (logos, fonts, approved images, music). Start a project from a package (Wizard and Manual), apply one to an existing project through a before/after card, save the current project's design as a package. Then, the owner's second part: hand a finished reel to the AI so that it proposes adjustments to the package from what was learned (what the user changed after generation, what was accepted or refused, the journal and memory), as proposals the owner accepts or refuses, never silent. Open points to settle before a brief: where packages live and how they are shared and versioned; whether approvals and rights answers of resources travel with the package or are asked again per project; what the AI may read of a reel to improve a package (design decisions, never the content); how a package maps to the skill's style sheet. Suggested slices: save and start from a package (no AI); apply to an existing project; AI refinement from reels; a manager window with versions.
- 2026-11-10 (owner), decisions on the Design System Manager above: (1) the user is the guarantor of the usage rights of licensed resources, so approvals and rights answers travel with the package; (2) a package is exported as one archive file (a zip with its own extension, to be chosen: the project already has a hidden `.studio/` folder, so a different extension avoids confusion); (3) the AI may read design decisions, the user's corrections and the journal of a reel to improve a package, never the content of texts or files; (4) a package can also be handed to the skill, to feed its style sheet.
