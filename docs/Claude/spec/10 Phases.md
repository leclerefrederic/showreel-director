# 10 Phases

> [!note] The plan as designed
> What was built, and when, is in [[phases-done]]. This note is the plan as it was designed; its text is not updated.

| Phase | Content | Done when |
|---|---|---|
| A (built) | ShowreelKit library, project model, library window, file editors, history, copilot panel with diffs | done; file tree and editors move to Advanced in A2 |
| A2 | App shell with the sidebar of blocks and statuses; Project block (parameters form); Resources block (drag and drop, statuses, MANIFEST.csv); file tree and editors hidden behind Advanced; typed copilot operations (`get_state`, `update_parameter`, `update_asset`, `open_block`) with readable cards; markdown regenerated from `showreel.json`; `process.json` and its check | A project can be created, parameterised and fed with resources without seeing a file |
| A3 | Mode switch (Beginner wizard, Expert), wizard framework with Project and Resources steps (later blocks plug in as they are built), "Decide later", progress; the app runs without a key (no Settings at launch, copilot shows "Connect AI"); native deterministic checks per block (feasibility, readability budget, asset rules, gate status) with green/red display; `ai` field in `process.json` and its check | A project can be parameterised and fed with resources through the wizard with no key configured |
| B | Look and technique block: palette, fonts, look board, background and effects pickers (engine preview spike first) | A validated look without a chat message |
| T (thin slice, before C and D) | Library window opens at launch by default. Storyboard block: list of scenes (add, edit, reorder, ditch; stable IDs; start/end, text, visual, feeling, handoff, linked resources) with native readability and feasibility checks; storyboard.md generated. Scene editor (minimal): one scene form plus OK / MODIFY / DITCH with note, the explicit Go. Build and preview (minimal): the AI generates the version folder from storyboard and decisions through the existing agent loop, the app runs build.py, harness and smoke test, shows red/green issues, and plays the reel in the app. "Rédiger avec l'IA" optional on the storyboard | A user can create a project, drop a logo, write scenes by hand, press Go and watch the generated reel play in the app |
| W1 (built, workspace shell) | The four-zone workspace replaces the sidebar of blocks: Library tabs (Resources, Scenes, Look elements) on the left, Viewer in the centre, Inspector with Copilot tab on the right, Storyboard timeline at the bottom; selection drives the inspector; project parameters and global look live in the inspector when nothing is selected; existing editors (palette, fonts, pickers) are moved into the library and inspector; Beginner wizard kept and ending in the workspace; data migration of 5.4 (scene library plus `storyboards`, archive with tombstone) | The same data as before is edited in the new layout, and nothing is lost |
| W1b (scene tree) | The scene tree in the Scenes tab with the five groups; Raw from the resources linked to the scene, Texts from the scene's text, Background and Look inherited from the project with the inherited/overridden marks and "Revert to project" (scene-level background and look overrides added to the data), Effects empty until W4 unless the scene already carries some; node statuses; selecting a node drives the viewer and the inspector | The composition of a scene is readable in one tree, with what is inherited clearly shown |
| W1c (scene content) | Content tab: ordered content items (text, image, sound) with colour (auto, palette role, custom), animation (auto or a library effect) and optional instruction; fixed or auto per attribute; control level (project default and per scene); reorder = priority; the tree groups follow the items; native checks of fixed values; the generation message for Build lists the items in priority order with fixed and auto marked; typed operations for add, update, remove and reorder items (cards, apply directly); skill export writes one text item per scene (skill bump) | A scene's content is mapped by hand, with the AI left to decide only what the user left open |
| W2 (film reel and music) | Frames with thumbnails in order with durations, transition markers between frames (type, duration, drag from the library), drag to reorder, drag edges to change the duration, on/off, add from the library, playhead; the project's music under the strip with its waveform and analysis (run `analyze_audio.py` from the app when a track is attached, read `analysis/beats.json`), snap to grid with a level picker (beat, bar, section, drop, off) and ripple, BPM and first-beat correction, music-dependent checks on the timeline, validation and Go | A film can be cut and timed on the timeline against the music, with scenes snapping to the grid |
| W2b (reel zoom, fix) | The reel follows the size of its panel: frame height and thumbnails scale with the panel height (aspect ratio kept, labels adapt), the music track gets its share of the height; the time scale is adjustable: slider, trackpad pinch, Cmd+Plus and Cmd+Minus, Fit film, Fit selection, horizontal scroll; zooming keeps the playhead (or the pointer) anchored; the ruler adapts (seconds and bars when zoomed out, beats when zoomed in) and labels thin out progressively; frame width stays proportional to duration at every zoom; the zoom is remembered per project in `.studio/ui.json` | A user can focus on a portion of the film and the strip is useful at any panel height |
| R1 (resources) | A structured Resources library: grouped by type (Images, Sounds, Music) then by state; automatic categorisation and filing on drop (type from extension and metadata, name by the skill's convention, original kept in `assets/source/`, prepared copy in `assets/prepared/` when it passes the automatic checks, registered in `MANIFEST.csv`); user-visible states Available, Used in (one tag per scene), Needs attention (staging in `assets/source/` only, hidden from the AI), plus Proposal and Declined as data; tags stored in `showreel.json` and filter by tag; central preview, and for music its metadata, cover image and a simple player; rights asked only when a file is flagged | A dropped file lands in the right group, named and registered, with no manual filing |
| R2 (AI resource analysis) | Optional AI analysis of resources that passed the automatic checks (watermark, recognisable person, third-party logo, personal data on a screenshot), under a per-project consent, flagged files never sent; results appear as Proposal (read-only reason, Approve or Decline) or Needs attention | The AI proposes associations and raises suspicions, the user decides |
| L (look is a project setting) | The Look elements tab leaves the left library, which keeps assets only (Resources, Scenes). The global look (looks board, palette, fonts, default background, mood, effects pack) moves into the project settings opened from a button in the top bar, together with the project parameters; application settings (key, gateway, model, environment) stay in the app menu. The catalogues of effects, transitions and backgrounds become pickers inside the scene inspector (Effects tab, per-scene Look), the transition inspector and the content item's animation, plus an optional floating Catalogue palette that stays a drag source | The library holds assets only, the look is a project parameter, and everything still drags |
| P1 (scene and look ergonomics) | Design system board in the viewer when the project settings are open; in each look editor the current choice is a card pinned at the top and the other options form a library below; scene Look overrides need an explicit switch per group (background, palette, fonts), with locked inherited values and a confirmation on drops; scene inspector tabs Settings, Composition (texts, images and sounds merged, in priority order), Effects, Look; the scene tree uses the same structure and a click opens the matching tab on that item | The scene tree and the inspector speak the same structure, and the look cannot be changed by accident |
| N (activity and notifications) | A task model in ShowreelKit for everything that runs in the background (Clap's generation, build and tests, audio analysis, thumbnails, resource checks, export): title, state running, succeeded or failed, optional progress, result and the action it offers; an Activity indicator in the project window's top bar with a list of running and recent tasks; non-modal in-app toasts when a task ends while the window is in front; native macOS notifications (UserNotifications) when the app or the window is in the background, a click opens the project at the right place (the build, the failing check); a failure says what failed and offers retry; app settings let the user switch each kind of notification on or off | The user can leave the app while something runs and is told when it is done or failed |
| M (project memory and history) | Three layers kept in the project and independent of the model: (1) an append-only journal `.studio/journal.jsonl` of every typed operation (author: user, Clap or skill; time; before and after; accepted or refused; the reason when given), refusals included so Clap does not propose them again; (2) a curated project memory `.studio/memory.json` (decisions with their reasons, user preferences, rejected options, constraints, open questions) written by Clap through a `remember` tool and fully visible, editable and deletable by the user in a "What Clap knows" view; (3) session history: transcripts per session with a short summary written at the end of each session, a browsable History view, and a resume that loads the memory and the last summaries instead of replaying raw transcripts, so changing the model or relaunching the project loses nothing. The memory and the journal feed the Decisions log and Assumptions sections of the generated `brief.md`; memory content is data, never instructions; no personal data or credentials are stored | Closing the app, changing the model or reopening the project keeps what was decided, validated, refused and modified |
| S (storyboard timeline redesign, supersedes W2b) | The strip redesigned as a proper editing timeline: opens zoomed to fit the whole film in the width; frames and thumbnails fill the available height with the aspect ratio kept; time zoom (slider with minus and plus icons, trackpad pinch, Cmd+Plus, Cmd+Minus, Cmd+0 to fit, Fit selection) anchored on the playhead or the pointer; horizontal scroll; legible ruler and labels (nothing under 11 pt); a dark editor-style timeline with real contrast; the music lane directly under the frames with a filled waveform, and an empty state that is a large drop target with a Choose music button; transition markers as small diamonds between frames with a type icon and a generous hit area, never covering a label; duration shown as a pill on each frame; disabled scenes dimmed; a toolbar with the title and counts on the left, transport (play, pause, timecode) in the middle, and on the right the zoom, a snap control (magnet icon with a level menu), a ripple toggle with an icon, Add scene, and one prominent primary action (Validate, then Give the Go); keyboard (space plays, arrows step by frame or scene) | A user can read, time and edit the whole film at a glance, and the strip is useful at any panel height |
| W3a (spike: scene modules and transition compositor) | Prototype in `showreel-director/engine/`: a scene is a module `render(g, lt, ctx)`; a reel-level layer assembles modules, keeps the background sequence and persistent elements, and a compositor mixes the outgoing and the incoming scene during a transition using the engine's transition effects; works in the player, `harness.js`, `smoke_player.js` and `export_mp4.js`; a two-scene test reel with a transition proves it; written report on feasibility, effort, risks and a recommendation on section 6.1. No change to Build yet | The owner decides on section 6.1 from the report |
| W3b (viewer and film integration) | Decision of 6.1 (2026-11-10, validated): adopt the compositor only (`SRF.film` and `SRT` as the runtime contract), keep one `main.js` that declares its scene modules; scene-by-scene generation is decided later after a style-drift experiment. Build: the build message asks for scene modules and one `SRF.film` call, with the montage (starts, durations, transitions) and the music grid supplied by the app; the harness can filter by scene. Viewer: follows the playhead and plays the built reel (transport: play, pause, scrub), and before a build shows a transition between two scene thumbnails; the six transitions that do not work between real scenes (Morph, Match cut, Ink/paper inversion, Curtain, Mirror split, Star reveal) are marked preview only and cannot be chosen for a montage | The user sees the scene and the film while editing, and a built reel uses the transitions of the montage |
| W4 (timing and viewer content) | Timing of each content item inside the scene (in and out), scene-wide effects in the Effects tab, thumbnails and viewer drawn from the content items (colour, animation), `storyboard.md` visual column generated from the content; skill export updated if needed (skill bump) | A scene is assembled and timed by hand and the viewer shows it |
| W5 (direct manipulation) | One drag and drop system used everywhere, replacing the Up and Down buttons: reorder by drag with a handle and an animated gap (content items, scenes in the library and in the reel, tree nodes, resources); drag a resource, background, effect, transition or look from the library onto a scene, a tree node, a content item or a reel marker, with drop targets that light up and refuse invalid drops with a reason; drag a file from the Finder onto a scene to add and link it; context menus (rename, duplicate, archive); inline editing where a form is not needed; undo and redo for every typed operation (Cmd+Z, Cmd+Shift+Z); spring animations on reorder, insert and removal; hover and selection states. Build reads the content items | The user assembles a reel by dragging, with fluid visual feedback and undo, and builds it |
| P (feel) | A design pass on the whole app, block by block from `docs/Claude/ux-notes.md`: spacing, type scale, materials and colours, SF Symbols, empty states, French and English interface, keyboard shortcuts | The app feels like a modern Mac editor, not a form-based application |
| PK1 (save and start from a package) | `PackageFile` in ShowreelKit (read and write `.studiopack`, canonical hash, validation of entries and sizes, integrity result); "Save design as package" in the project settings (what goes in, name, author display name, note, new version of the same id); the library of packages in Application Support; "Start from a package" at project creation in both ways in (the Wizard asks only what the package leaves open); the import card with the rights confirmation and "Not signed"; the `.studiopack` document type registered so a double-click opens the import card; the project records its origin; no AI | A user saves the design and resources of a project as a package, sends the file, and a colleague starts a new project from it, with the rights confirmed by the colleague |
| PK2 (apply to an existing project) | Apply a package to an existing project through a before/after card (settings changed, resources added, locked scenes that inherit the change); update to a newer version of the same id; drift shown between a project and its package | An existing project can adopt or update a package without surprises |
| PK3 (improve a package from a reel) | Clap reads only design decisions, the user's corrections, accepted and refused proposals and scene states of a finished reel, and proposes changes to the package as cards with reasons; accepted proposals make a new version; refused ones are remembered | The package learns from the reels made with it, and the owner decides every change |
| PK4 (package manager and skill) | A manager window (packages, versions, compare two versions, duplicate, export, delete); a script of the skill that turns `design.json` into the style sheet; `portability.md` and `capabilities.json` updated together (skill bump) | Packages are managed in one place and usable from the skill alone |
| C | Storyboard timeline and Scene editor with live preview, scene review and the explicit Go | Storyboard validated and Go given from the app |
| D | Build and preview, Deliver, release gate | A full reel built, checked and exported from the app |

Tests per phase: round trips of `showreel.json`, golden files for the generated markdown, import of markdown-only projects, typed operations against a scripted agent, `process.json` against `SKILL.md` in `check.py`, extended `--selftest`.

Status of each phase: see [[phases-done]], the one table of every phase with its prompt, its report and its versions. The table above is the original plan and does not list the phases added after PK1.
