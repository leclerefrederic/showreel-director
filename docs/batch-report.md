- *What Build refused:* nothing refused; it silently relied on the AI to list approved font assets in `project.json`, and the build message told the AI to "set the family in tokens and let the reel fall back to a system font" for any font that was not an approved asset. With no file in the project, the film fell back to a system font and nothing said so.
- *Embedding:* `project.json` lists `fonts: [{family, weight, path}]`; `build.py` embeds each as a base64 `@font-face` (woff2 or woff when fontTools is there, the raw file otherwise) and guards the files against the manifest (approved, listed). The engine therefore can embed fonts as data URLs already. No `FontFace` URL is needed for the built page (`engine-host.js` uses `FontFace` only for the app's previews).
- *Fetching:* `fetch_font.py` works from a terminal; the app did not call it. The app now does the lookup and download itself in ShowreelKit (`GoogleFontsSource`), with an injected source for tests, because the app needs the file list for the card and a readable error. No Python is needed for it.
