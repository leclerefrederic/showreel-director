# Showreel Studio (native macOS app)

A chat plus a preview pane that run the `showreel-director` skill with its own agent loop, so the look board, the pickers, the effects lab and the scene cards open next to the conversation.

Pieces: the package has two targets. `ShowreelKit` (a library, no window) holds the agent loop (`Agent.swift`, a `MessagesTransport` protocol so tests can script the model), the tools (`Tools.swift`: `bash`, `read_file`, `write_file`, `list_dir`, `ask_user`, `show_page`, `screenshot_preview`, `get_state`, `propose_edit`), the `AgentUI` protocol, the project model (`ProjectStore`, `ShowreelFile` for `showreel.json` schema 1, `ProjectImporter` for markdown-only projects, history in `.studio/history`, chat history in `.studio/chat`, `ProjectLibrary`, `FileWatcher`) and the parsers (markdown tables, CSV, line diff). `ShowreelStudio` (the executable) is the SwiftUI shell: a library window, one window per project (a sidebar of blocks with statuses on the left, the selected block in the middle, the copilot chat on the right), settings, setup screen. Blocks come from `shared/process.json` (Project, Look and technique, Resources, Storyboard, Scene editor and Build and preview are built; Deliver shows "coming soon"); the file tree and editors live in an Advanced panel that is off by default. The preview pane is a `WKWebView` because the pickers and boards are HTML. The API key lives in the Keychain. The system prompt is the skill's `SKILL.md` plus `shared/addendum.md`; the tools are defined in `shared/tools.json`. HTTPS uses the macOS trust store.

`showreel.json` (schema 1, the contract of `docs/Claude/studio-spec.md` 5.1b, unknown keys kept) is the source of truth; `brief.md`, `style-sheet.md` and `storyboard.md` are generated from it, with their hashes in `.studio/generated.json`, and a file changed outside the app is never overwritten (the app offers a re-import). The copilot changes project data through typed operations (`update_parameter`, `update_asset`) that the user reads as plain cards and accepts or refuses; other prose and text files go through `propose_edit` as a diff. A project can switch on "Apply directly". The Resources block writes `assets/MANIFEST.csv` in the format of `scripts/organize_assets.py` (a test runs the script's `--check` on it). Every save, by the user or the copilot, keeps the previous version in `.studio/history/<file>/` (last 50), with diff and restore.

```
cd app-swift
swift build                 # compile
swift run                   # run from the source tree (resources found by walking up)
swift test                  # ShowreelKit tests: parsers, project model, history, tools, agent loop
./make-app.sh               # build/ShowreelStudio.app, ad-hoc signed
```

In the app: the library window lists the projects (New project, Open folder, pin, archive); each project opens in its own window; the gear opens Settings (API key in the Keychain, gateway base URL and Bearer or x-api-key, model; `ANTHROPIC_BASE_URL` is also read); then describe the reel. `python3`, `node` and `ffmpeg` must be on the PATH (`bash` runs in a login zsh that also sources `~/.zshrc`).

Environment: at launch the app runs `setup-env.sh --check` (bundled in the app) and shows a setup screen until Python 3, the Python packages (numpy, fonttools), Node.js, npm, jsdom, canvas and ffmpeg are present; **Install missing** runs `setup-env.sh --install` (a Python venv and the node modules under `~/Library/Application Support/ShowreelStudio/env`, node and ffmpeg through Homebrew when it is installed, never Homebrew itself). Python 3 comes from the Command Line Tools (`xcode-select --install`). A link lets the user continue without, in reduced mode. The script also runs from a terminal: `bash tools/setup-env.sh --check` or `--install`.

Icon: `Icon/AppIcon.png` is the 1024 px master, drawn by `python3 tools/make_icon.py` (an original design: a film reel with a play triangle). `Icon/AppIcon.icns` is the finished macOS icon (sizes 16 to 1024 px, retina included), committed with the master; `make-app.sh` copies it into the app.

Signing: the build looks for a code-signing certificate named `Showreel Studio Local` (create it once in Keychain Access, Certificate Assistant, type Code Signing, self signed), then an Apple Development identity, else it signs ad hoc. A stable identity keeps the Keychain's "Always Allow" for the API key across rebuilds.

Status: written without a Swift compiler at hand, so expect compile fixes; the GitHub workflow `swift.yml` builds it on a macOS runner.

Look and technique block: the engine of the skill (`core.js`, `kit.js`, `backgrounds.js`, the effect files, and the helper block of `engine/effects-lab.html`) runs in a hidden `WKWebView` (`EngineRenderer`, host API in `shared/engine-host.js`), from the skill folder inside the app bundle only. It draws the thumbnails of the look board, the backgrounds and the effects in the project's palette and font; frames are cached in `.studio/thumbs/`. The palette is stored in `decisions.palette` as background, text, accent, accent 2, with a deterministic contrast check; fonts come from `engine/fonts-free.json` with the bundled woff2 previews registered with CoreText, and a font that is not in the free list gets a licence warning (embedding flag and manifest notes); the look board offers three of the starting looks in `shared/look-packages.json`, none pre-selected. Every pick is a typed operation (`update_decision` for the copilot) shown as a card. `ShowreelStudio --selftest` renders an effect and a background and checks the pixels.

Storyboard, Scene editor, Build and preview (phase T, a thin slice): `showreel.json` holds the scenes as an ordered array with stable IDs (never reused or renumbered; a ditched scene stays in the list), edited through `add_scene` and `update_scene` operations (cards for the copilot, plain operations for the forms); `storyboard.md` is generated from it. The Go is the gate `review`: it is only ever set by the Go button (operation `.gate("review")`, refused unless the storyboard is validated and every scene is OK or ditched), no tool can set it, and a change to a scene after the Go takes it back. The build block needs the Go; the copilot writes `vN/project.json` and `vN/main.js` from one message (`BuildRunner.prompt`), then the app runs the skill's `build.py`, `harness.js` and `smoke_player.js` through the login shell (`Shell`, `BuildRunner.run`), shows each result as green or red, sets the `build` and `verify` gates from those results, and plays `vN/dist/index.html` in a web view. Outputs are written in the project folder only. Without a key the block says that writing a version needs one; a version that already exists can still be tested and played. `SHOWREEL_LAUNCH_LOG=<file>` makes the app write the windows it shows two seconds after launch, to check that only the Library opens.

Editing workspace (phase W1): the window is a video-editor layout. The Library on the left has three tabs (Resources, Scenes, Look elements: looks, palettes, fonts, backgrounds, effects, scene transitions); the Viewer in the centre draws the selected scene or element with the engine (`EngineService.sceneFrames` for a scene, a stand-in that follows the global look until layers exist); the Inspector on the right shows the selection (a scene: duration, review OK / MODIFY / DITCH with a note, feeling, passage note, linked resources; a resource; a look element with its actions), or the project parameters and the global look when nothing is selected, and holds the Copilot tab (and the Files tab in Advanced); the Storyboard strip at the bottom has one frame per scene in order, each on or off, drag to reorder, with the validation and the Go. Build and preview replaces the Viewer when asked. Beginner mode keeps the wizard and ends in the workspace; Expert mode opens the workspace at once. `showreel.json` holds a scene library (`scenes`: own `duration`, `archived`) and `storyboards` (`items: {scene, enabled, start?, end?, transition}`); a phase T file (start and end inside each scene) is read as one scene library and one montage and written in the new shape on the first save (`ShowreelFile.migratedMontage`); deleting a scene archives it and its ID stays reserved; DITCH archives it and switches it off in every montage. Typed operations: `add_scene`, `update_scene`, `enable_scene`, `move_scene` (cards before and after; apply directly per project). `process.json` lists the zones of the workspace (library, viewer, inspector, storyboard, build, deliver) and gives each step an `area` (project, resources, look, storyboard, scene, build) that the checks and the wizard use.
